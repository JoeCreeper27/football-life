# FootballLife ⚽ 足球人生模擬器

12 歲從國中球隊開始，選一個出身國家、選一種出身背景，
決定要進足球學校還是留在校隊，然後一路往上爬到五大聯賽，
最終目標是把自己的代表隊帶進世界盃。純文字生涯養成，種子化，每一個決定都算數。

> 玩法概念致敬 [yakyulife](https://github.com/LeoGGcat/yakyulife)（CC BY-NC 4.0），詳見 [NOTICE.md](NOTICE.md)。

---

## 快速開始

**不需要安裝任何東西就能玩**（純 ES modules）：

```bash
python3 -m http.server 8000
# 開 http://localhost:8000
```

要用 Vite 開發與建置成單一 HTML：

```bash
npm install
npm run dev      # 開發伺服器
npm run build    # 產出 dist/index.html（單檔，可直接丟 GitHub Pages）
npm run sim      # 跑 2000 局平衡模擬（隨機國家）

# 單一國家對表（國家碼見下方階梯表）
node tools/balance-sim.js 600 balanced TW
```

推上 `main` 後 GitHub Actions 會自動建置並部署到 Pages
（Settings → Pages → Source 選 **GitHub Actions**）。

## 架構

```
src/
├─ engine/            ★ 純函式，零 DOM 相依，可在 Node 裡跑
│  ├─ rng.js          種子化亂數（mulberry32）
│  ├─ data.js         所有平衡數值：能力、位置、國家、出身、聯賽階梯、球會、事件卡、特性
│  ├─ state.js        狀態建立、能力成長、綜合評價、陣中地位
│  ├─ sim.js          出場時間、賽季數據、傷病、薪資、衰退
│  └─ flow.js         年度流程狀態機
├─ main.js            UI：記錄流 + 選項按鈕 + 狀態列
tools/balance-sim.js  蒙地卡羅平衡模擬
docs/SPEC.md          完整開發規格書
```

### 引擎介面只有兩個函式

```js
import { createState } from './src/engine/state.js';
import { run, answer } from './src/engine/flow.js';

const s = createState('abc123', {
  name: '王小明', number: 10, group: 'FW',
  nation: 'TW',      // TW JP KR US BR AR GB ES DE IT FR PT NL
  origin: 'local',   // local 純本地 / mixed 混血 / immigrant 移民
});
s.step = 'YEAR_START';

let r = run(s);                  // 推進到下一個決策點
r = answer(s, r.pending.options[0].v);   // 回答後繼續推進
// r = { cards: [...], pending: {...} | null, state }
```

`cards` 是純資料（`{tone, title, html}`），UI 層才決定怎麼畫。
因此同一份引擎可以：

- 在瀏覽器跑遊戲
- 在 Node 裡跑萬次模擬調平衡
- 之後移植 Kotlin 做 Android，或放在 server 上用 `{seed, actionLog}` 重放驗證排行榜成績（防作弊）

### 決定論

所有遊戲隨機都走 `Rng`，並記錄 `cursor`。因此：

- 同種子 ＋ 同選擇 ＝ 同一段人生，`?seed=xxx` 就是可分享的劇本
- 存檔只要存 `{seed, cursor, state}` 就能完整還原
- 純視覺效果請用 `Math.random()`，**不要**污染這條序列

⚠️ 任何新增／刪除 `rng` 呼叫的規則改動都會讓舊種子結果漂移。發版時請更新 CHANGELOG。

## 核心機制

| 系統 | 說明 |
|---|---|
| **陣中地位** | `squadGap = 綜合 − (聯賽基準 + 球會等級 + 位置競爭)` → 核心／主力／輪替／替補／看台席，決定出場率。**能力夠了也不一定有球踢**，這是與棒球版最大的差異 |
| **球會等級** | 豪門／爭冠／中游／保級，獨立於聯賽等級。豪門板凳 vs 中游主力是每季的真實抉擇 |
| **能力養成** | 20–80 球探量表、OOTP 式潛力天花板、階梯成本、蓄力槽（未滿一級不蒸發，扣值 1:1 立即生效） |
| **韌帶量表** | 由 `(速度+對抗) × 踢法 × 出場負荷` 累積；爆表時二選一：動手術（報銷一年、速度回春）或打封閉硬撐（55%，失敗重大斷裂） |
| **非均勻衰退** | 31 歲起速度體能大跌、閱讀比賽的能力不跌 → 天然導出「速度型早退、技術型長青」與位置轉型 |
| **出身國家** | 13 個國家，各有不同的青訓水準、國內聯賽階梯、代表隊實力，以及有沒有大學足球這條退路。台灣國內天花板只有企業聯賽，巴西／西班牙一出生就在職業體系裡 —— 這是遊戲最主要的難度旋鈕 |
| **出身背景** | 純本地（徵召門檻低）／混血（潛力更高，18 歲時可改代表另一國）／移民（起步吃虧，但旅外年齡窗口寬） |
| **養成分岔** | 國中三年後二選一：進足球學校（訓練骰多，但沒有升學退路）或留校隊（成長普通，保留大學與第二人生） |
| **轉會窗** | 升級／同級轉戰其他地區／降級／外租／返回家鄉，每個選項都標明地區。升級目的地刻意跨洲分散，所以「要去哪個地區」本身就是一個決策 |
| **成長四階段** | 潛力期（≤18，骰面 2–8）→ 成長期 → 巔峰期（成本 ×1.5）→ 維持期（≥29，只有技術類還練得動）。總點數控制住但重壓在 24 歲前，身分在 18 歲之前就成形 |
| **原型** | 15 種原型不是開局選的，是前幾年加點長出來的。18 歲時依能力分布給 2–3 個選項，選定後主修成本 ×0.7、非主修 ×1.3 —— 成長方向被收窄，這才是原型的重量。走到極致會進化，31 歲跑不動時會有位置會議 |
| **球迷聲望** | 0–100，影響主場表現、薪資、分紅與引退評價。≥90 且同隊 ≥8 年會球衣退休，≤20 則被掛牌求售。負面事件扣得比正面加得兇 |
| **兵役** | 台灣與韓國限定，20–24 歲強制觸發：體育替代役／入伍（少一季）／海外役男延期 |
| **世界盃** | 代表隊整體實力由國家決定，個人能力最多再加 +8。弱國晉級是全遊戲最大的情緒高點，強國則是擠進名單本身就很難 |

## 生涯階梯

聯賽分成 7 個層級，同一層有多個地區的聯賽；你的出身國家決定「哪些算國內、
從哪一層開始、國內能爬到哪」。要往上就得旅外，而旅外有年齡窗口。

| 層級 | 亞洲 | 歐洲 | 南美 | 北美 |
|---|---|---|---|---|
| 7 五大聯賽 | — | 英格蘭／西班牙／德國／義大利／法國 | — | — |
| 6 五大次級 | — | 英式次級／歐陸次級 | — | — |
| 5 歐洲跳板 | — | 葡超／荷甲／跳板聯賽 | — | — |
| 4 洲際頂級 | J1／K1 | — | 巴甲／阿甲 | MLS |
| 3 次級職業 | J2／K2 | 歐洲第三級 | 巴乙 | 美職次級 |
| 2 低階職業 | J3／K3 | 歐洲第四級 | 巴丙／阿乙 | 美國三級 |
| 1 半職業 | 台灣企業聯賽／JFL／K4 | 歐洲第五級 | 南美地區聯賽 | 美國業餘 |

台灣的國內天花板就是第 1 層 —— 想再往上，**只能出國**。這是台灣 run 的核心設定。

## 目前的平衡狀況

`npm run sim` 的實測結果（1500 局，balanced 策略，隨機國家）：

| 指標 | 目前 | 目標 | |
|---|---|---|---|
| 登上五大聯賽 | 6.2% | 6–10% | OK |
| 踢進世界盃 | 台灣 3.0%／巴西 ~43% | 依國家而定 | OK |
| 確立原型 | 99.6% | — | OK |
| 登上洲際頂級以上 | ~87% | 25–45% | **偏高** |
| 生涯至少一次重傷 | ~86% | 40–65% | **偏高** |
| 25 歲前退出 | 0.4% | 10–22% | **偏低** |

各國登上五大聯賽的比例（同一份模擬）：

```
台灣 1%  日本 4%  韓國 4%  美國 1%  巴西 9%  阿根廷 8%
英國 4%  西班牙 10%  德國 12%  義大利 7%  法國 8%  葡萄牙 8%  荷蘭 6%
```

**還沒解決的**：中段門檻（第 2–4 層）太好過，只要不受重傷幾乎都能爬到本洲頂級聯賽；
傷病基礎率仍然偏高。建議的下一步：

1. `data.js` → 拉高 `LV` 第 3、4 層的 `min`，讓洲際頂級真的是一道門檻
2. `sim.js` → `injuryRisk()` 降 `CONF.baseInjury`，重傷判定改成需連續高負荷才觸發
3. 每次改完跑 `npm run sim 2000`，並用 `npm run sim 600 balanced TW` 之類的單國模式對表

> 註：模擬機器人「有得升就升」，所以「一輩子沒旅外」在模擬裡永遠接近 0%，
> 這個指標要看真人玩家的行為，不適合拿模擬值對表。
