# Part A — 成長節奏重構

## A1. 問題診斷

現況：每季固定 3–6 顆骰、`abCost` 只看能力現值。造成三個問題：

1. **每一季感覺一樣** — 15 歲和 27 歲的加點體驗沒有差別，玩家感受不到「黃金期」
2. **點數攤太薄** — 外場 9 個能力欄位，平均一季 4.5 點分下去，每項只動 0–1，選擇沒有份量
3. **總量通膨** — 20 個賽季累積下來輕鬆突破所有聯賽門檻（實測 27% 登上五大，目標 6–10%）

## A2. 解法：四階段成長曲線

總點數控制住，但**重壓在 24 歲前**。

| 階段 | 年齡 | 每季骰數 | 骰面 | 成本修正 | 設計意圖 |
|---|---|---|---|---|---|
| **潛力期** | ≤18 | 3 顆 | 2–8 | ×1.0 | 一季能動 8–10 點，身分在這裡成形 |
| **成長期** | 19–23 | 3 顆 | 1–6 | ×1.0 | 標準養成，原型主修開始拉開差距 |
| **巔峰期** | 24–28 | 2 顆 | 1–5 | ×1.5 | 幾乎練不動，重點轉向數據與榮譽 |
| **維持期** | ≥29 | 1 顆 | 1–4 | ×2.0 | 只有技術類（pas/vis/pos/fin）能練，其餘鎖住 |

實作位置：`flow.js` 的 `STEPS.PRE_DICE`

```js
const PHASE = p =>
  p.age <= 18 ? { n: 3, lo: 2, hi: 8, cost: 1.0 }
: p.age <= 23 ? { n: 3, lo: 1, hi: 6, cost: 1.0 }
: p.age <= 28 ? { n: 2, lo: 1, hi: 5, cost: 1.5 }
:               { n: 1, lo: 1, hi: 4, cost: 2.0 };
```

`abCost()` 加上階段乘數與原型修正（見 B3），最後 `Math.ceil`。

維持期的能力鎖定清單放 `data.js`：

```js
export const LATE_GROWABLE = ['pas', 'vis', 'fin', 'pos', 'dis', 'hea'];
```

29 歲後非清單內的能力在加點 UI 上直接標灰不可點——這會很自然地把老將推向「轉型後腰／中衛」的路。

## A3. 骰子改成有面額差異

現在骰面 1–6 均勻，改成階段區間後（潛力期 2–8）會出現「這顆 8 要灌哪」的爽感。
再加一條：**同一顆骰只能投一個能力**（現況已是如此），但允許**合併投擲**——
UI 上長按某個能力可以把剩餘所有骰一次投進去，適合已經想專精的玩家。

## A4. 預期的平衡效果

| 指標 | 現況 | 改後預期 |
|---|---|---|
| 登上五大聯賽 | 27% | 8–12%（巔峰期練不動，天花板被潛力值鎖死） |
| 一輩子沒離開台灣 | 0% | 30%+（潛力期沒抽好就上不去） |
| 青訓期受傷的代價 | 幾乎沒有 | 極高（少一個 ×3 倍率的年份） |

改完務必跑 `npm run sim 2000` 對表。

# Part B — 原型系統（Archetype）

## B1. 核心設計

**原型不是開局選的，是前幾年加點長出來的。**

- **18 歲季末**（或職業第一年結束）觸發「你踢的是哪一種球」事件
- 系統掃描能力分布，找出符合資格的原型，給玩家 **2–3 個選項**
- 一旦選定，後續成長方向被收窄——這才是原型的重量所在

## B2. 原型表

`req` = 相對同組其他能力的相對領先（不是絕對值），確保各階段都判定得出來。

### 前鋒 FW

| 原型 | 主修 | 產能修正 | 特色 |
|---|---|---|---|
| **禁區之狐** | fin, hea, vis | 進球 ×1.35、助攻 ×0.6 | 不吃速度 → 衰退期仍能進球，生涯最長 |
| **速度殺手** | pac, fin, dri | 進球 ×1.2、助攻 ×0.9 | 31 歲後產能斷崖，但巔峰期最強 |
| **全能中鋒** | phy, hea, fin, pas | 進球 ×1.0、助攻 ×1.3 | 平衡型，隊友加成事件多 |
| **偽九號** | vis, pas, dri, fin | 進球 ×0.85、助攻 ×1.6 | 可與 AM 互相轉型 |

### 邊路 W

| 原型 | 主修 | 產能修正 | 特色 |
|---|---|---|---|
| **邊路魔術師** | dri, pac, vis | 助攻 ×1.5、進球 ×0.8 | 球迷聲望成長最快（過人集錦） |
| **內切射手** | fin, dri, pac | 進球 ×1.3、助攻 ×0.9 | 需要慣用腳與邊路相反的設定 |

### 中場 MF

| 原型 | 主修 | 產能修正 | 特色 |
|---|---|---|---|
| **中場發動機** | sta, phy, def, pas | 進球 ×1.0、助攻 ×1.0 | 出場率 +8%，但韌帶負荷 ×1.2 |
| **中場大師** | pas, vis | 助攻 ×1.4 | 不吃速度體能 → 40 歲還能踢，評分天花板最高 |
| **十號核心** | vis, pas, dri | 助攻 ×1.6、進球 ×1.1 | 金球獎機率加權最高 |
| **防守屏障** | def, phy, hea | 助攻 ×0.7 | 零封加成，獎項少但續約穩 |

### 後衛 DF

| 原型 | 主修 | 產能修正 | 特色 |
|---|---|---|---|
| **中衛磐石** | def, hea, phy | 零封 ×1.3 | 隊長袖標機率 ×2 |
| **出球中衛** | pas, vis, def | 零封 ×1.1、助攻 ×1.4 | 現代足球的高價值型 |
| **助攻邊衛** | sta, pac, dri, pas | 助攻 ×1.5 | 衰退期被迫轉中衛的經典劇本 |

### 門將 GK

| 原型 | 主修 | 產能修正 | 特色 |
|---|---|---|---|
| **撲救之神** | ref, pos | 零封 ×1.35 | 評分波動大，單場英雄事件多 |
| **門線清道夫** | dis, aer, pos | 零封 ×1.1 | 出球型，適配豪門 |

## B3. 機制效果

```js
// data.js
export const ARCHETYPE = {
  poacher: {
    n: '禁區之狐', group: 'FW', major: ['fin','hea','vis'],
    req: p => p.ab.fin >= 45 && p.ab.fin - p.ab.pac >= 4,
    out: { g: 1.35, a: 0.6, cs: 1 },
    ageBias: 'late',        // 衰退對此原型影響小
    events: ['fox_instinct','offside_king'],
    evolve: { to: 'clinical', cond: s => 進球累計 >= 120 },
  },
  // ...
};
```

四個效果：

1. **成本** — 主修能力 `abCost × 0.7`，非主修 `× 1.3`（無條件進位）
2. **潛力** — 選定原型時，主修能力的 `pot` 各 **+4**（上限 80）
3. **產能** — `sim.js` 的 `POS_OUTPUT` 再乘上原型的 `out` 係數
4. **事件** — 解鎖該原型的專屬事件卡（見 Part C 第六類）

## B4. 原型進化與轉型

**進化**（同一條路走到極致，純榮譽向，影響獎項權重）

- 禁區之狐 → **冷血終結者**（生涯 120 球）
- 中場大師 → **節拍器**（生涯 300 場且評分均值 ≥7.3）
- 邊路魔術師 → **看台起立者**（球迷聲望 ≥85）
- 撲救之神 → **不可逾越**（單季零封 ≥18）

**轉型**（31 歲後、速度掉到門檻下時觸發，這是全遊戲最有戲的一刻）

| 原路 | 可轉 | 文案方向 |
|---|---|---|
| 速度殺手 | 禁區之狐 | 「你跑不過他們了，但你比他們早兩秒知道球會落在哪」 |
| 邊路魔術師 | 十號核心 | 從邊線移進中路 |
| 助攻邊衛 | 中衛磐石 | 往後退一條線 |
| 中場發動機 | 防守屏障 / 出球中衛 | 跑不動了，改用位置感 |

轉型成功：主修能力重置為新原型、`pot` 再 +3、生涯延長 3–5 年、解鎖特性〈第二春〉。
轉型失敗或拒絕：產能係數持續衰減，兩季後強制面對引退。

## B5. UI 影響

加點介面依原型排序：**主修 3–4 項置頂並標色**，其餘折疊在「其他能力」底下（預設收合）。
這是解決「選項太多」的關鍵——不是刪掉能力，是讓玩家一眼看到該練哪三個。

# Part C — 事件庫

## C1. Schema 擴充

現有 `EVENTS` 只能改能力值，新事件需要副作用。建議擴充成：

```js
{
  n: '事件名',
  for: '*' | 'GK' | 'OUT' | 'PRO',       // 現有欄位
  cond: s => boolean,                     // ★新增：觸發條件
  weight: 1,                              // ★新增：抽中權重，預設 1
  once: true,                             // ★新增：整局只會出現一次
  gt: '成功文案', bt: '失敗文案',
  g: { fin: 2, fanRep: 10 },              // 能力 + 新數值都走同一張表
  b: { fin: -2, fanRep: -10 },
  fx: (s, win, rng) => { /* 強制轉會、解除隊長、禁賽等副作用 */ },
}
```

抽卡處（`flow.js` 的 `STEPS.MID_EVENTS`）改成先過 `cond` 再依 `weight` 加權抽樣，
並排除 `once` 且已觸發過的（記在 `s.career.seenEvents[]`）。

## C2. 新數值：球迷聲望 `fanRep`

放在 `s.career.fanRep`，範圍 0–100，初始 50。影響：

| 影響面 | 規則 |
|---|---|
| 主場表現 | `d += (fanRep - 50) / 25`（±2） |
| 續約條件 | `fanRep ≥ 75` 時薪資係數 ×1.1；`≤ 25` 時球會傾向出售 |
| 引退評價 | `legacyScore += (fanRep - 50) * 12` |
| 球衣分紅 | `fanRep ≥ 70` 每季額外收入 |
| 特殊結局 | `fanRep ≥ 90` 且同隊 ≥8 年 → 球衣退休、球場外塑像 |

轉隊時 `fanRep` 回歸到 55（新東家重新認識你），但若前隊 `fanRep ≥ 80`，
記進 `s.career.legends[]`，引退時列出「這些球場永遠記得你」。

# Part D — 實作順序建議

1. **`fanRep` 先做** — 它是一半新事件的載體，沒有它事件寫了也無處著陸
2. **Schema 擴充**（`cond` / `weight` / `once` / `fx`）＋ 抽卡邏輯改加權
3. **成長四階段**（Part A）＋ 跑 `npm run sim 2000` 確認階梯回到目標區間
4. **原型系統**（Part B）— 判定、成本修正、產能係數、UI 折疊
5. **事件庫分批進**：先第一類（球迷）＋ 第五類（台灣），這兩類差異化最強
6. **原型專屬事件**最後做，因為要等原型系統穩定

每完成一步都跑一次平衡模擬，並記錄到 CHANGELOG（規則改動會讓舊種子漂移）。

# Part E — 注意事項

- **不要使用真實球員姓名**。上面所有事件都寫成「原型」而非特定人物；文案裡也不要出現可辨識的真人指涉（球會、教練、隊友一律虛構或不具名）。真人 ＋ 虛構醜聞是誹謗風險。
- **負面事件要有出路**。每張負面卡都應該有翻身路徑（例如〈更衣室毒瘤〉可透過連兩季高評分 ＋ 換隊解除），否則玩家會覺得被懲罰而不是被講了一個故事。
- **`fanRep` 不要做成單調上升**。負面事件的扣分幅度要明顯大於正面加分，才會讓玩家真的猶豫。
