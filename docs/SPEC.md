## 第一部分：yakyulife 架構解析

### 0. 事實盤點

| 項目 | 內容 |

| 儲存 | localStorage 僅存 主題 / 字級 / 手機版切換 / 球員名 / 背號。**遊戲無中途存檔** |

### 1. 決定論核心（整個產品的病毒傳播支點）

```js
let SEED = new URLSearchParams(location.search).get('seed') || Math.random().toString(36).slice(2,10);
function seedInit(str){ /* FNV-ish 字串雜湊 */ }
function R(){ /* mulberry32 變體，回傳 [0,1) */ }
const ri=(a,b)=>a+Math.floor(R()*(b-a+1));
const pick=a=>a[Math.floor(R()*a.length)];
const chance=p=>R()*100<p;
const N0=sd=>(R()+R()+R()+R()-2)/2*sd*2;   // 四次抽樣近似常態
```

- **所有**遊戲隨機都走 `R()`，因此「同種子 ＋ 同選擇 ＝ 同一段人生」。分享網址 `?seed=xxx` 就是分享劇本。
- 骰子滾動動畫刻意用 `Math.random()`，**不污染 seeded 序列**。這個細節很關鍵，複製時務必照做。
- 代價：任何規則調整（新增一次 `ri()` 呼叫）都會讓舊 seed 的結果漂移，舊分享連結失效。原作靠 CHANGELOG 版本號承認這件事。

### 2. 流程引擎：步驟佇列 + CPS

```js
let S=null, stepQ=[];
function startYear(){ stepQ=[phasePre,phaseMid,phaseEnd]; divider(...); nextStep(); }
function nextStep(){ if(S.done){stepQ=[]; return;} const f=stepQ.shift(); if(f)f(); }
```

- 一年 ＝ 三個階段函式排隊執行；每個子系統（感情、事件卡、傷病、轉隊、續約）都是 **continuation-passing style**：`loveEvent(next)`、`drawEvents(n, done)`、`faFlow(o)`，靠 callback 串接非同步的玩家選擇。
- 好處：極簡、無狀態機框架、易插入新步驟。
- 壞處：callback 深度嵌套、無法回溯、規則與 UI 綁死（例如 `dposReview()` 同時算守位門檻又畫按鈕）。**足球版建議改良（見第二部分 §2）。**

### 3. 全域可變狀態 `S`

`newState()` 回傳一顆約 60 個欄位的巨型物件，涵蓋：能力 `ab`、潛力上限 `pot`、`traits`（25 個布林）、`stats`（依 CPBL/NPB/MLB/MINOR 分桶累積）、`honors[]`、合約 `ct`、感情 `love`、傷病 `tj/bigInj/injNext`、年資 `svc/faElig`、守位 `dpos/dposYears`。

無 immutable、無 reducer、無序列化。這是「沒有存檔」的直接原因。

### 4. 數值模型：一切繫於單一標量 `d`

```js
d = 能力聚合 q − 該層級基準 par
```

- 投手 `q=(vel+ctl+brk)/3`；野手 `q=con*0.5+pow*0.2+eye*0.18+spd*0.12`。
- `d` 一路推導出：出賽數、ERA/打擊率、獎項機率、薪資、升降級、續約年限、名人堂評分。
- 所有輸出都是 `clamp(base + d*係數 + N0(噪音))` 的形式。
- **這是最值得抄的設計**：一個標量把「能力 → 表現 → 收入 → 聲望」全部串起來，調參集中，不需要真的模擬比賽。

### 5. 資料表驅動

`LV`（層級 par/min/場次/所屬組織）、`EVENTS`（17 張事件卡）、`TRAIT_N/TRAIT_FX`、`DP_TH`（守位門檻）、`POS_ADJ_RUNS`（守位薪資調整）、`TEAM_COLOR` 全部是頂層 `const` 字面量。改平衡＝改表，不改邏輯。

### 6. 成長系統

- **OOTP 式潛力天花板**：出生時洗牌能力清單，1 項頂尖（72–80）、1 項優質、1 項中上、其餘平庸。投手因只有 4 項能力，天花板刻意壓更兇（避免全能怪）。
- **階梯式成本**：`abCost()` 依現值分段（野手 1/2/3 點、投手 1/2/4/7 點），超過潛力上限再乘 3～4 倍。
- **蓄力槽 `carry`**：未滿一級的點數保留不蒸發；扣值卻是 1:1 立即生效（跌比練快）。
- UI：`allocUI({dice:[...]} | {pool:n}, label, done)` 支援骰子逐顆指定與點數池，含「復原」堆疊。

### 7. 結算分享圖

`shareImage()` 用**兩段式 canvas**：先在 8×8 的丟棄式 canvas 上跑完整排版流程量測總高度，再開真正尺寸的 canvas 繪製，最後 `toDataURL('image/png')`。這是純前端做長圖分享的標準解法，直接沿用。

### 8. 可複製的三個產品決策

1. **文字 log ＋ 按鈕**：`card(cls,title,html)` append-only 記錄流，`choose(title,opts)` 出選項。整個遊戲 UI 只有這兩個原語 ＋ 頂部 `board()` 狀態列。零美術成本。
2. **年度摺疊區塊**：`divider()` 每年開一個 `.yr-block`，前年自動收合，超過 `MAX_YEARS` 移除最舊 DOM。長生涯不會炸記憶體。
3. **避免版／真實版雙軌命名**：球隊全用改編名（「台中猛獁」「阪神猛虎」），規避 IP 風險又保留辨識度。**足球版必抄**（歐洲球會 IP 更兇）。

### 9. 明確的技術債（足球版該修的）

| 問題 | 影響 |
|---|---|
| 單檔 4,000 行 | 多人協作、AI 輔助改動都痛苦 |
| 無測試 | 改一個係數不知道會不會讓五大聯賽登陸率從 8% 變 40% |
| 規則與 DOM 混寫 | 無法做離線平衡模擬、無法移植 Android |
| 無存檔 | 長生涯（30+ 年）只能一次玩完，手機切走就沒了 |
| 模擬只有單一 `d` | 足球需要「出場時間」這條獨立軸，單標量不夠用 |

## 第二部分：足球版開發規格

### 1. 產品定位

**一句話**：從台灣高中足球隊出發，經企業聯賽 → 日韓 → 歐洲跳板聯賽 → 五大聯賽，最終目標是把中華隊帶進世界盃。

**與棒球版的三個關鍵差異（＝賣點）**

| 軸線 | 棒球版 | 足球版 |
|---|---|---|
| 核心焦慮 | 能力夠不夠打上一軍 | **能力夠了也不一定有比賽踢**（陣中地位／租借） |
| 球隊維度 | 只影響冠軍率與配色 | **球會等級**獨立於聯賽等級：豪門板凳 vs 中游主力的永恆抉擇 |
| 終極夢想 | 名人堂 | **中華隊踢進世界盃**（現實中未曾發生，情緒張力最大） |

### 2. 技術架構

#### 2.1 選型建議

保留原作「純前端 / 靜態託管 / 零後端」的傳播優勢，但**把引擎抽離成純函式套件**：

```
football-life/
├─ packages/
│  ├─ engine/              # 純 TS，零 DOM 相依
│  │  ├─ rng.ts            # seeded PRNG（mulberry32）+ ri/pick/chance/gauss
│  │  ├─ state.ts          # PlayerState 型別 + createState(seed, setup)
│  │  ├─ reducer.ts        # (state, action) => {state, effects[]}   ★核心
│  │  ├─ sim/
│  │  │  ├─ season.ts      # 賽季數據模擬
│  │  │  ├─ minutes.ts     # 出場時間模型（足球獨有）
│  │  │  ├─ injury.ts      # 傷病與負荷量表
│  │  │  ├─ transfer.ts    # 轉會／租借／合約
│  │  │  ├─ awards.ts      # 個人與團隊榮譽
│  │  │  └─ legacy.ts      # 生涯傳奇評分
│  │  └─ data/             # ★全部 JSON：leagues / clubs / events / traits / i18n
│  └─ ui-web/              # 前端：log + choose + board，可用 vanilla 或 Preact
├─ tools/
│  ├─ balance-sim.ts       # 跑 10,000 seeds 機器人，輸出分布報表
│  └─ snapshot-test.ts     # seed 回歸快照
└─ dist/index.html         # 建置時 inline 成單檔（保留原作的單檔部署優勢）
```

- 用 Vite + `vite-plugin-singlefile` 建置成**單一 HTML**，部署仍是 GitHub Pages 丟一個檔案。開發期分模組，產出仍單檔。
- 引擎純函式 ⇒ 三個附加價值：
  1. **可離線跑平衡模擬**（backend 思維：把遊戲當成一個可測的函式）
  2. **可移植 Android**：`engine` 用 Kotlin 重寫或直接 KMP；UI 走 Compose，或先用 WebView + Capacitor 上架驗證。
  3. **可做防作弊排行榜**：客戶端只上傳 `{seed, actionLog[]}`，server 用同一份 engine 重放驗證最終評分。這是原作做不到的。

#### 2.2 流程引擎（取代 stepQ + callback）

改成明確的狀態機 ＋ 待決佇列：

```ts
type Phase = 'PRESEASON'|'WINTER_WINDOW'|'MIDSEASON'|'SEASON_END'|'OFFSEASON'|'RETIRED';

interface Pending { id: string; title: string; options: Option[] }

interface GameState {
  seed: string; rngCursor: number;       // ★存 cursor 才能存檔
  phase: Phase; pending: Pending | null;
  player: Player; club: ClubState; career: CareerLog;
}

function step(s: GameState, action?: Action): { next: GameState; cards: Card[] }
```

- `rngCursor` 序列化 ⇒ **支援中途存檔**（原作最大缺口）。
- `cards[]` 是純資料（`{tone, title, html}`），UI 層才決定怎麼畫 ⇒ 引擎可在 Node 裡跑。
- 每個決策點回傳 `pending`，UI 渲染按鈕，玩家選擇後回呼 `step(s, action)`。無 callback 嵌套。

### 3. 能力系統

**量表 20–80**（沿用球探量表，玩家熟悉；也對應 FM 的 1–20 ×4）

| 分類 | 能力 |
|---|---|
| 共通 | 體能 `sta` |
| 外場球員（9 項） | 射門 `fin`、傳球 `pas`、盤帶 `dri`、速度 `pac`、對抗 `phy`、防守 `def`、頭球 `hea`、視野決策 `vis` |
| 門將（5 項） | 撲救 `ref`、制空出擊 `aer`、站位 `pos`、腳下傳球 `dis`（＋`sta`） |

**潛力天花板**（出生暗抽，同 OOTP 式洗牌）

- 外場：1 項 72–80、1 項 64–74、1 項 56–68、其餘 46–62
- 門將：只有 5 項，天花板更集中 → 1 項 70–80、1 項 60–70、其餘 48–58（複製原作對投手的處理）

**成長成本**

| 現值 | 外場 | 門將 |
|---|---|---|
| <60 | 1 | 1 |
| 60–69 | 1 | 2 |
| 70–74 | 2 | 3 |
| 75+ | 3 | 4 |
| 超過潛力上限 | ×3 | ×4 |

未滿一級進蓄力槽；扣值 1:1 立即生效。

**季前擲骰**：每年 3–6 顆（35/40/20/5%），逐顆指定。傷後復健年只擲 2 顆。

開局選四大類：`GK` / `DF` / `MF` / `FW`。**登上頂級聯賽才登錄細分位置**（同原作守位邏輯）。

門檻相對該聯賽基準 `B`：

| 位置 | 主要門檻 | 次要 | 薪資係數 |
|---|---|---|---|
| ST 中鋒 | fin B+4 | phy B、hea B+1 | ×1.20 |
| W 邊鋒 | pac B+4 | dri B+3 | ×1.15 |
| AM 前腰 | vis B+4 | pas B+3、dri B+2 | ×1.15 |
| CM 中場 | pas B+2 | vis B+2、sta B+2 | ×1.05 |
| DM 後腰 | def B+3 | phy B+2、pas B−2 | ×1.02 |
| FB 邊後衛 | sta B+4 | pac B+3、def B | ×1.00 |
| CB 中衛 | def B+4 | hea B+3、phy B+3、pac B−4 | ×0.98 |

### 6. ★ 出場時間模型（足球版核心新機制）

棒球版只有「能不能待在這一層」；足球版必須回答「**待在這裡有沒有球踢**」。

```
squadGap = ovr − (league.par + clubTier.bonus + positionCompetition)
```

| clubTier | 名稱 | par 加成 | 冠軍率 | 洲際盃 | 薪資係數 |
|---|---|---|---|---|---|
| 1 | 豪門 | +6 | 高 | 每年 | ×1.6 |
| 2 | 爭冠／歐戰區 | +3 | 中 | 常有 | ×1.2 |
| 3 | 中游 | 0 | 低 | 偶爾 | ×1.0 |
| 4 | 保級 | −3 | 極低 | 無 | ×0.8 |

`squadGap` → 陣中地位與出場率：

| squadGap | 地位 | 出場率 | 說明 |
|---|---|---|---|
| ≥ +5 | 絕對核心 | 88–95% | 可能拿隊長袖標 |
| +2 ~ +5 | 主力 | 75–88% |  |
| −1 ~ +2 | 輪替 | 45–70% |  |
| −4 ~ −1 | 替補 | 18–40% | 觸發〈板凳生涯〉負面壓力 |
| < −4 | 看台席 | 0–10% | 兩季不動 → 能力停滯懲罰 |

**玩家每季前的核心決策**（三選一，這是整個遊戲最好玩的地方）：

1. **留隊競爭** — 有機會奪冠／踢歐冠，但可能整季看台
2. **要求外租** — 降一級但保證主力，累積出場數與成長，租約結束回歸
3. **申請轉會** — 主動降級去中游球隊當核心，換取數據與國家隊位置

出場率會乘進所有賽季數據（進球、助攻、零封）與獎項資格，也影響傷病負荷與續約報價。

### 7. 賽季模擬

每季四階段（比棒球多一個冬窗）：

```
PRESEASON  季前特訓（擲骰加點）＋ 陣中地位確認 ＋ 踢法選擇
   ↓
MIDSEASON  事件卡 ×3 ＋ 感情事件 ＋ 傷病檢定
   ↓
WINTER_WINDOW  冬窗（僅在地位 = 替補/看台 或 有外部報價時觸發）
   ↓
SEASON_END  數據結算 ＋ 獎項 ＋ 洲際賽 ＋ 薪資 ＋ 轉會/續約 ＋ 國際賽（隔年）
```

**數據推導**（單標量 `d` ＋ 出場率 `m`）

```
外場 q = fin*w1 + pas*w2 + dri*w3 + pac*w4 + vis*w5 + phy*w6   （依位置切換權重表）
d = q − league.par
apps   = round(league.games * m * seasonFactor)
goals  = clamp(base(位置) + d*k_g + gauss(σ), 0, …) * apps/38
assists= …
CS(零封) = 門將/中衛專用，取決於 d 與 clubTier
rating = 6.30 + d*0.045 + gauss(0.12)     // 球評評分，UI 顯示用
```

位置權重表（JSON）決定同一 `d` 對中鋒與中衛的意義完全不同：中鋒吃 `fin/pac`，中衛吃 `def/hea/phy`，門將另走一套。

**踢法選擇**（對應原作投球強度，影響負荷）

| 踢法 | 效果 | 負荷倍率 |
|---|---|---|
| 全場壓迫 | d+1、進球/搶斷 +8% | ×1.25 |
| 標準 | 標準 | ×1.0 |
| 節省體力 | d−1，30 歲後可解鎖〈節奏大師〉 | ×0.7 |

### 8. 傷病與衰退

- 基礎受傷率 15%，疊加：出場率（滿場 +6%）、洲際盃 +5%、國家隊 +8%、年齡（30 歲 +5%、33 歲 +10%）。
- **小傷**：缺陣 4–10 週，砍當季數據 25–50%，40% 留下能力後遺症。
- **大傷**：整季報銷，`pac −5`、`sta −3`，50% 機率隔年狀態未恢復（`seasonFactor 0.7`）。
- **韌帶量表（對應原作 TJ）**：每季依 `(pac + phy) × 踢法 × 出場負荷` 累積，滿分 50。
  - 觸發 → 二選一：
    - **動十字韌帶手術**：量表歸零、報銷一年、`pac` 回復 +3~+8（現代醫學回春）
    - **打封閉硬撐**（55%）：保住當季，量表 −20；失敗 → 重大韌帶斷裂，隔年也報銷、`pac` 再 −5
  - 累計 2 次 → `pac` 直接砍半，被迫轉型（後腰/中衛）或引退。
  - 隱藏特性〈鋼鐵膝蓋〉：連兩次硬撐成功解鎖，量表上限 100、硬撐成功率 85%。
- **衰退（足球特有的非均勻衰退）**：31 歲起 `pac/sta −3`／年，`phy −1`，而 `pas/vis` **不減甚至 +1**。35 歲起加劇。42 歲強制引退。
  → 天然導出「速度型球員早退、技術型球員長青」的真實感，也讓位置轉型成為主動策略。

### 9. 轉會、合約與租借

| 機制 | 規格 |
|---|---|
| 青訓合約 | 18 歲前簽，3 年，年薪低、球會擁有優先續約權 |
| 職業合約 | 年限 1–5 年（足球不像 MLB 有 10 年約）；30 歲以上上限 3 年、34 歲以上上限 1 年 |
| 解約金條款 | 簽約時可選「加入低解約金（年薪 ×0.9）」→ 未來大俱樂部激活機率大增。經典足球決策 |
| 自由轉會 | 合約剩 6 個月可與他隊預簽（Bosman），簽字費 = 年薪 ×0.5 |
| 租借 | 1 季，可含買斷選項；租借期間薪資由租方付 60–100% |
| 轉會費 | `fee = f(ovr, 年齡, 剩餘合約年限, 上季數據)`，只顯示不進玩家口袋，但影響新東家對你的期待值（＝ squadGap 的隱性門檻 +2） |
| 經紀人 | 每次談判抽 5–10%；可選「換強力經紀人」→ 報價數 +2 但抽成 ×2 |
| 續約談判 | 三選一：加薪續約（×1.15）／要求解約金條款／拒絕續約進入自由身 |

冬窗只在「地位 ≤ 替補」或「爆發表現引來報價」時觸發，避免每季都被打斷。

### 10. 國家隊與世界盃（情緒核心）

- **徵召門檻**：ovr ≥ 該時期中華隊第 23 名水準（動態，約 48 起跳）。
- **賽事循環**：世界盃資格賽（每 4 年一輪，2 年賽程）→ 亞洲盃（4 年）→ 東亞盃（2 年）→ 世界盃（4 年，需晉級）。
- **中華隊實力**：每屆隨機生成整體強度，**個人能力最多提供 +10% 加成**（沿用原作「棒球是團隊運動」的節制設計）。
  - 但足球版加一條：若玩家 ovr ≥ 62（五大聯賽主力級），額外解鎖「一人扛整隊」事件，資格賽晉級率 ×1.4。這是給頂級 run 的獎勵，也是全遊戲最大的情緒高點。
- **世界盃晉級** = 隱藏成就〈把台灣帶上世界舞台〉，直接進入傳奇評分最高檔並解鎖專屬引退場景。
- 國家隊出賽 → 傷病率 +8%、賽後下季 `sta` 消耗；特性〈國家隊之魂〉可消除。
- **歸化抉擇**（可選劇本）：25 歲前若在歐洲效力且未代表中華隊出賽，觸發他國徵召邀請 → 接受（國家隊層級躍升，但失去世界盃劇本與台灣球迷評價）／拒絕。

### 11. 榮譽與傳奇評分

**個人**：聯賽 MVP、金靴（射手王）、助攻王、金手套（門將零封王）、年度最佳陣容、最佳新人、亞洲足球先生、**金球獎**（需五大聯賽 ＋ 歐冠級表現）
**團隊**：聯賽冠軍、國內盃、洲際盃（亞冠 / 歐冠 / 歐聯）、世俱盃
**國家隊**：亞洲盃名次、世界盃晉級／名次、賽會 MVP


### 12. 隱藏特性（目標 25–30 個）

**正向**：金童（22 歲前擲出 5 次 6）、鐵人、大場面先生（歐冠淘汰賽進球 ×3）、一人一隊（同隊 10 年 ＋ 冠軍）、隊長袖標、定位球專家、越洋拓荒者（首位登陸五大的台灣球員）、節奏大師、國家隊之魂、鋼鐵膝蓋、學院派、大器晚成、小校之光、努力仔

**負向**：玻璃人（30 歲前 2 次大傷）、板凳生涯（連續 2 季出場率 <20%）、更衣室毒瘤、社群媒體災難、經紀人傀儡（3 次以上跟隨經紀人建議轉會）、只會這個（單一維度領先 ≥22）、失去信心（連 2 季 d ≤ −6）、假摔王

觸發條件全部不顯示，靠玩家摸索 —— 這是原作社群討論度的主要來源，必須保留。

### 13. 事件卡（目標 22–25 張）

沿用「保守 ±1（成功率 +20%）／照常 ±2／全力一搏 ±3（成功率 −15%）」三選一結構與溢出規則（能力滿上限時加點轉為當季數據加成）。

足球版卡片：加練定位球 `fin+2`、健身房增肌 `phy+2/pac−1`、衝刺訓練 `pac+2/拉傷+10%`、一對一防守課 `def+2`、影像分析 `vis+2`、教練戰術改造（位置適性）、與門將的默契訓練（GK）、記者會失言、社群媒體風波、球迷見面會、更衣室內鬨、冬窗傳聞、代言邀約、宵夜文化、季中低潮、青訓小將挑戰你的位置、國家隊集訓、時差與客場長征。

### 14. UI/UX 規格

- 沿用 append-only `card` log ＋ `choose` 按鈕列 ＋ 頂部 `board` 狀態列（年齡／年份／綜合／生涯薪／出場率／地位）。
- 年度摺疊區塊 ＋ DOM 上限回收。
- 四套主題：草皮綠記分板（預設）／球場電子看板／體育報紙／現代儀表板。手機／電腦雙版型、大字級。
- 頂部額外顯示**足球版專屬**：陣中地位徽章（核心／主力／輪替／替補／看台）＋ 球會等級星等。
- 結算分享圖：兩段式 canvas 量測 → 繪製 → PNG。內容含頭像色塊、生涯路線圖（聯賽階梯視覺化）、生涯數據表、榮譽牆、特性標籤、種子碼 QR。
- PWA：runtime Blob manifest（照抄原作做法）。

### 15. 資料模型（TypeScript 摘要）

```ts
type Abil = 'sta'|'fin'|'pas'|'dri'|'pac'|'phy'|'def'|'hea'|'vis'|'ref'|'aer'|'pos'|'dis';
type PosGroup = 'GK'|'DF'|'MF'|'FW';
type DetailPos = 'GK'|'CB'|'FB'|'DM'|'CM'|'AM'|'W'|'ST';
type SquadRole = 'KEY'|'STARTER'|'ROTATION'|'BENCH'|'STAND';

interface Player {
  name: string; number: number; age: number; posGroup: PosGroup; pos: DetailPos | null;
  ab: Record<Abil, number>;
  pot: Record<Abil, number>;
  carry: Record<Abil, number>;
  traits: Record<string, boolean>;
  removed: string[];
  injury: { load: number; acl: number; big: number; nextRisk: number; rehab: number };
  love: LoveState;
}

interface ClubState {
  league: LeagueId; club: ClubId; tier: 1|2|3|4;
  role: SquadRole; minutesPct: number;
  contract: { years: number; annual: number; releaseClause: number | null; loanFrom?: ClubId };
  yearsAtClub: number;
}

interface CareerLog {
  seasons: SeasonStat[];        // 依 top 層級分桶累積
  honors: Honor[];
  caps: number; intlGoals: number; worldCups: number[];
  salaryTotal: number;
}

interface GameState {
  seed: string; rngCursor: number; version: string;
  year: number; phase: Phase; pending: Pending | null;
  player: Player; club: ClubState; career: CareerLog; done: boolean;
}
```

存檔 = `JSON.stringify(GameState)` 進 localStorage（含 `rngCursor` 與 `version`；版本不符時提示「規則已更新，此存檔可能不相容」）。

### 16. 測試與平衡（backend 思維的優勢區）

1. **快照回歸**：固定 100 個 seed × 3 種機器人策略（保守／平衡／激進），輸出最終 `legacyScore` 與關鍵里程碑；CI 上比對 baseline JSON，差異超過閾值就 fail。
2. **蒙地卡羅平衡**：`tools/balance-sim.ts` 跑 10,000 局，檢查目標分布：

| 指標 | 目標 |
|---|---|
| 登上五大聯賽 | 6–10% |
| 登上 J1/K1 | 25–35% |
| 一輩子沒離開台灣 | 40% |
| 拿到金球獎 | < 0.5% |
| 帶中華隊晉級世界盃 | 2–4% |
| 25 歲前退出足球 | 15–20% |
| 生涯至少一次大傷 | 55% |

3. **不變量斷言**：能力永不超過 80、不超過潛力上限（除非溢出路徑）、合約年限符合年齡上限、出場數 ≤ 聯賽場次。
4. **效能**：一局完整生涯（20+ 賽季）在 Node 上須 < 5ms，才跑得動萬次模擬。
